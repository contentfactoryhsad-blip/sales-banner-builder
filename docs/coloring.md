# 흑백 텍스처에 색 입히기 — 무엇을 왜 쓰는가

배너 배경은 **흑백 텍스처 한 장**이고, 여기에 프로모션 색을 입혀서 쓴다.
방식을 네 가지 검토했고 A·B 가 서로 다른 것을 쓴다. 이 문서는 **왜 그렇게 됐는지**를
남긴다 — 지웠던 방식을 누군가 다시 제안하는 일을 막기 위해서다.

## 결론부터

|  | A 시안 | B 시안 |
|---|---|---|
| 색 입히기 | **Overlay** (CSS 블렌드) | **Gradient map** (Canvas 픽셀 치환) |
| 배경 블러 | 없음 (0) | 17.5px · 배경별 0.7배 조정 |
| 셰이드 | 검정 `rgb(0,0,0)` · overlay · 0.85 | 흰색 `rgb(255,255,255)` · normal · 1.0 |
| 프레임 바탕 | 메인→조합 그라데이션 | 흰색 |
| Edit 표시 순서 | Overlay → Gradient map | Gradient map → Overlay |

두 방식 다 Edit 에서 고를 수 있다. 시안별로 **기본값을 먼저** 보여줄 뿐이다.

## 문제 — 왜 색이 탁해지는가

텍스처 위에 색을 **섞으면**, 결과 밝기를 텍스처가 정해버린다. 그 밝기대에서 낼 수
있는 채도에는 한계가 있어 회색빛이 돈다. 우리 텍스처는 특히 불리하다.

```
b-bg-01  밝기 123 ~ 234   평균 204
b-bg-03  밝기 155 ~ 240   평균 188
b-bg-05  밝기 133 ~ 213   평균 155
```

- **순수한 검정도 흰색도 없다.** 가장 어두운 픽셀이 123 이다.
- **밝기 폭이 전체의 31% 뿐인 저대비 텍스처**다.
- **배경마다 평균이 다르다** (155 / 188 / 204).

이 세 가지가 아래 방식들이 무너지는 이유다.

## 검토한 방식

### 1. Overlay — CSS `mix-blend-mode` (A 채택 / B 에서는 탈락)

`<img>` 에 블렌드 모드를 걸어 섞는다. **A 는 이걸 쓴다.**

B 에서 탈락한 이유는 위의 "섞으면 탁해진다" 그대로다. B 는 `luminosity` 로 섞었는데
필터 후 평균이 143 이라, 그 밝기대의 낮은 채도밖에 못 냈다.

A 가 그대로인 건 더 나아서가 아니라 **종전 결과가 확정본이고 블러가 0 이라 바꿀
이유가 없어서**다.

### 2. Multiply — CSS `mix-blend-mode: multiply` (삭제)

곱셈이라 **무조건 어두워진다.** 결과 = 색 × (밝기/255) 이므로 우리 텍스처에서는
색이 **52~84% 로 눌린다.** 그래서 보정을 걸어야 했다.

```
contrast(0.56)    160~232 → 146~186    명암 차이는 살리고
brightness(1.37)  146~186 → 200~255    전체를 흰색 쪽으로
```

**보정 상수가 텍스처마다 달라야 하는 게 문제였다.** 배경 5종의 평균이 155·188·204 로
제각각이라 한 벌의 상수로는 어떤 배경에선 어둡고 어떤 배경에선 날아간다.
선택지·타입·렌더 갈래·보정 상수까지 전부 지웠다 (커밋 `02d4500`).

### 3. 마스킹 — `mask-image` / `globalCompositeOperation = 'source-in'` (미채택)

흑백을 알파 마스크로 써서 색을 오려내는 방식. "가장 쨍하다"고 알려져 있지만
**우리 텍스처에는 뚫을 검정이 없다.**

알파가 `123/255 ≈ 0.48` 에서 `240/255 ≈ 0.94` 사이에서만 움직이므로, 완전히 뚫리지도
채워지지도 않는 **반투명 판**이 된다. 뚫린 만큼 뒤의 흰 바탕이 비쳐 오히려 더 뿌옇고,
유리 결의 명암 구조도 사라진다.

이 방식은 패턴에 진짜 흑백이 다 있는 경우를 전제한다. 우리는 전제가 다르다.

### 4. Gradient map — Canvas 픽셀 치환 (B 채택)

포토샵 "그레이디언트 맵"과 같은 원리. **섞지 않고 갈아끼운다.**

`getImageData` 로 픽셀 밝기를 읽어 256칸 대응표(LUT)로 색을 바꾸고 `putImageData` 로
되돌린다. 캔버스 블렌드 모드(`globalCompositeOperation`)를 쓰는 게 아니다.

```
가장 어두움  →  메인색 × 0.32     (그림자)
     중간    →  메인색            ← 가장 넓다
     밝음    →  조합색
가장 밝음    →  조합색 + 흰색 50%  (하이라이트)
```

여기에 **자동 밝기 보정**이 붙는다 — 텍스처 평균 밝기가 항상 LUT 한가운데(=메인색)로
오도록 감마를 건다. **그래서 배경을 바꿔도 상수를 다시 잡을 필요가 없다.**
Multiply 가 무너진 지점이 정확히 여기다.

부수 효과로 **굽기(PNG 내보내기)에도 유리하다.** ZIP 은 `html-to-image` 로 DOM 을
SVG(foreignObject) 안에 넣어 래스터하는데, 여기서는 `backdrop-filter` 같은 게 안 먹혀
유리 박스를 따로 흉내내고 있다(`emulateGlass`). 캔버스는 이미 그려진 그림이라
그대로 구워진다.

## 정리

| 방식 | 하는 일 | 왜 안 되나 |
|---|---|---|
| Overlay | 섞는다 | 결과 밝기를 텍스처가 정함 → 채도 한계 |
| Multiply | 곱한다 | 무조건 어두워짐 → 텍스처별 보정 필요 |
| 마스킹 | 뚫는다 | 뚫을 검정이 없음 → 반투명 판 |
| **Gradient map** | **갈아끼운다** | **섞지 않으므로 탁해질 수 없음** |

앞의 셋은 전부 텍스처의 원래 밝기에 결과가 끌려다닌다. 네 번째만 그렇지 않다.
