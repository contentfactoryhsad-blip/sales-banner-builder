# Safari 에서 배너가 다르게 보이는 이유

같은 코드인데 Chrome 은 멀쩡하고 Safari 만 깨진다. 이 문서는 **왜 그런지**와
**Safari 까지 같게 만들려면 무엇을 해야 하는지**를 남긴다.

## 결론부터

이 렌더러는 CSS 에서 **브라우저 구현 차이가 가장 심한 세 가지**에 전부 기대고 있다.

| 기능 | 쓰는 곳 | Safari 에서 생기는 일 |
|---|---|---|
| `filter: blur()` | **B 배경 블러 35** | 요소 경계 밖 번짐 처리가 달라 **가장자리가 날아간다** |
| `mix-blend-mode` | **A 배경 색 입히기**(overlay 0.9), 장식 도형 | `backdrop-filter` 와 겹치면 합성 그룹이 다르게 잡혀 **덧칠이 빠진다** |
| `backdrop-filter` | 글래스 박스·글래스 스티커 | 레이어가 많아지면 합성이 불안정. 위 블렌드를 깨는 방아쇠이기도 하다 |

셋 다 "여러 레이어를 합성하는" 기능이고, 합성 순서·그룹 경계는 명세가 느슨해
브라우저마다 다르다. **B 는 색을 캔버스에 구워 넣어서**(Gradient map) 블렌드에
의존하지 않고, **A 는 CSS 블렌드로 섞는다** — A 만 깨지는 이유가 이것이다.
자세한 건 [coloring.md](./coloring.md).

## 브라우저 문제인 걸 어떻게 확인했나

"서버(로컬)는 되는데 웹(배포)만 안 된다"로 오래 헤맸다. 배포 상태부터 의심했는데
**배포는 죄가 없었다** — 로컬은 Chrome, 웹은 Safari 로 보고 있었을 뿐이다.

번들 해시를 비교하면 코드가 같은지 1분 만에 갈린다. Vite 해시는 **내용 기반**이라
같으면 소스가 같다.

```bash
# 라이브에 올라가 있는 번들
curl -s https://sales-banner-builder.lge-d2c.com/ | grep -oE 'assets/index-[A-Za-z0-9._-]+\.js'
# 로컬 빌드 결과
npm run build | grep -oE 'assets/index-[A-Za-z0-9._-]+\.js'
```

**둘이 같은데 화면이 다르면 코드 문제가 아니다.** 그때부터는 브라우저·캐시·줌·
선택한 옵션을 본다. 다르면 그냥 배포가 아직 안 끝난 것이다(Railway 는 보통 1~2분).

> 다음에 "여기선 되는데 저기선 안 된다"가 나오면 **브라우저부터 물어볼 것.**
> 이번엔 그걸 안 물어서 배포·캔버스·블렌드를 차례로 헛짚었다.

## 증상 1 — B 배경 가장자리가 날아간다 (고침)

`filter: blur()` 는 색만이 아니라 **알파도** 흐린다. 그래서 흐린 요소의 가장자리는
반투명해지고 뒤 바탕이 비친다. 번지는 폭은 대략 블러값의 두 배다.

배경 상자의 어떤 변이 프레임 경계에서 그 폭보다 가까우면, 그 변이 **프레임 안에서**
부옇게 날아간 것처럼 보인다. Chrome 은 번짐을 요소 밖으로 더 넉넉히 그려서 티가
안 났고, Safari 에서 그대로 드러났다.

**고친 방법:** 모자란 만큼 배경 상자를 키워 번짐을 프레임 밖으로 밀어낸다
(`inflateBg`). 보정 자체는 원래 있었는데 **"증상이 보이는 사이즈만" 손으로 7개**를
골라 걸어 뒀던 게 문제였다. 전 사이즈를 재보니 배경 5종 기준 **16개**가 모자랐다.

| 목록에 없어서 날아가던 사이즈 | 모자란 양 |
|---|---|
| criteo-1024x768 · pmax-1200x628 | 왼쪽 22.8px |
| criteo-970x250 | 왼쪽 13.3px |
| dv360-300x1050 | 아래 20.7px |
| criteo-160x600 | 아래 12.1px |
| criteo-480x320 · criteo-120x600 · dv360-120x60 · criteo-1200x1200 | 2~4px |

목록을 없애고 `need()` 가 판단하게 했다. 여유가 충분한 변은 0 을 돌려주므로 나머지
25개는 값이 그대로고, 무늬가 커지는 폭은 최대 3.2%(대부분 1.6% 이하)다.

⚠ **일부러 안 닿게 배치한 변(여백이 음수)은 채우지 않는다.** 그건 번짐이 아니라
원본 배치이고 그 자리는 흰 셰이드가 덮는다. criteo-1200x628 의 왼쪽 78px 이 그
경우다 — 네 변 모두 여유가 419px 이상이라 애초에 이 보정과 무관하다.

**그래도 남으면:** `inflateBg` 의 `spread = blurPx * 2` 에서 그 배수만 키우면 된다.
Safari 의 번짐 폭이 계산보다 넓다는 뜻이다.

## 증상 2 — A 배경이 흑백으로 굳는다 (화면만 · 아직 안 고침)

AD Media 확인창에서 일부 사이즈의 배경이 색이 안 입혀진 **흑백 텍스처**로 남는다.

확정된 조건 네 가지 — 전부 사용자가 재현해 준 것이다:

- **글래스 박스가 있을 때만** 생긴다. 박스를 끄면 아무리 눌러도 멀쩡하다.
- **A 시안만** 생긴다. B 는 글래스를 골라도 멀쩡하다.
- **줌을 당기면 색이 돌아오고, 줌을 아웃하면 다시 깨진다.** 같은 배너가 배율만으로
  갈리므로 **상태값은 멀쩡하고 그리는 순간의 합성이 실패**하는 것이다. 확인창은
  41장을 한 겹(`transform: scale(z)`, 기본 0.32)에 담아 축소하는데, 축소된 합성
  레이어 위에 유리까지 겹치면 사파리가 블렌드를 건너뛴다.
- **받은 PNG 는 멀쩡하다** (2026-08-24 사용자 확인). 즉 **화면 전용 증상**이다.
  굽는 경로는 확인창을 안 탄다 — `useBannerZip` 이 화면 밖에서 원본 크기로 그리고
  `emulateGlass` 로 `backdrop-filter` 를 아예 빼므로, 블렌드를 깨는 방아쇠가 없다.

> 그래도 고칠 값은 있다. 확인창에서 색을 잘못 보고 판단하게 되기 때문이다.

이 두 조건이 같은 곳을 가리킨다:

```
글래스 박스  = backdrop-filter      ← 유일하게 박스가 만드는 합성 효과
A 만 깨짐    = mix-blend-mode 사용   ← B 는 캔버스에 구워서 블렌드가 없다
```

`backdrop-filter` 가 방해할 수 있는 건 **CSS 블렌드 합성**뿐이다. A 는 흑백 텍스처를
`mix-blend-mode: overlay` 로 프로모션 색 위에 얹어 색을 입히는데(덧칠 구조), 그
블렌드가 끊기면 **덧칠만 빠진 원본 흑백**이 그대로 남는다. 증상과 정확히 같다.

> 정확한 Safari 내부 동작까지는 확인하지 않았다. 위는 두 재현 조건이 가리키는
> 가장 유력한 설명이고, 아래 고치는 방법은 **어느 쪽이 원인이든 통한다** —
> 블렌드 자체를 없애기 때문이다.

## Safari 도 같게 만들려면

### 1. A 의 색 입히기를 블렌드에서 캔버스로 옮긴다 (근본 해결)

B 가 이미 그렇게 한다. 섞지 않고 **픽셀을 갈아끼우면** 합성 그룹이라는 게 없어서
`backdrop-filter` 가 뭘 하든 안 깨진다. 유리 블러도 그대로 둘 수 있다.

단, A 는 확정본이라 **겉모습이 달라지면 안 된다.** overlay 는 명세에 공식이 있으므로
그대로 재현하면 픽셀이 같아진다. `Cb` = 바탕(프로모션 그라데이션), `Cs` = 텍스처,
둘 다 0~1 정규화:

```
overlay(Cb, Cs) = Cb <= 0.5  ?  2 · Cs · Cb
                             :  1 − 2 · (1 − Cs) · (1 − Cb)
```

여기에 불투명도 `α = 0.9`(`textureOpacity`)를 얹은 최종 합성:

```
Co = (1 − α) · Cb  +  α · overlay(Cb, Cs)
```

`GradientMapBackground` 와 같은 자리에서 캔버스에 구우면 된다. 바탕이 그라데이션이라
픽셀마다 `Cb` 가 다르므로, LUT 한 벌로는 안 되고 **바탕 그라데이션도 같이 그려서**
픽셀 단위로 계산해야 한다.

**검증:** 바꾸기 전후로 1200×628 을 PNG 로 받아 픽셀 차이를 재는 게 가장 확실하다.
눈으로만 보면 미세한 채도 차이를 놓친다.

### 2. 확인창의 `backdrop-filter` 부하를 줄인다

41장 × 박스 최대 6개 = **최대 200개**가 걸린다. 가장 비싼 효과를 200번 거는 셈이라
Safari 가 아니어도 무겁다. 두 갈래가 있다:

- **보이는 배너만 그린다**(가상화) — 유리도 색도 하나도 안 바뀐다. 제일 깔끔하지만
  줌·팬과 맞물려야 해서 구현이 가장 크다.
- **확인창에서만 `backdrop-filter` 를 뺀다** — 채움·테두리·하이라이트는 두고 흐림만
  뺀다. 간단하지만 줌인하면 유리가 밋밋해진다. **한 번 시도했다가 되돌렸다**(아래).

### 3. 번짐 계수를 올린다

증상 1 이 Safari 에서 아직 남으면 `spread = blurPx * 2` 의 배수만 키운다.
한 줄이고 부작용은 무늬가 조금 더 커지는 것뿐이다.

## ⚠ 화면만의 문제가 아니다 — 굽는 PNG 도 브라우저가 만든다

`bannerExport.ts` 는 `html-to-image` 로 DOM 을 SVG(foreignObject) 에 넣어 굽는데,
**래스터는 사용자 브라우저가 한다.** 미리보기와 같은 렌더러를 그대로 쓰기 때문에
화면이 다르면 **납품하는 PNG 도 다르다.**

`backdrop-filter` 는 foreignObject 에서 아예 안 먹어 이미 `emulateGlass` 로 우회했지만,
`filter: blur()` 와 `mix-blend-mode` 는 **굽는 경로에도 그대로 남아 있다.**

**증상 2 는 굽는 쪽까지 오지 않는 것으로 확인됐다**(위 참고). 하지만 `filter: blur()`
와 `mix-blend-mode` 가 굽는 경로에 남아 있는 건 그대로이므로, 다른 증상까지 안전하다는
뜻은 아니다.

**확인 방법:** 같은 배너를 Chrome 과 Safari 에서 각각 받아 파일을 비교한다.

```bash
# 크기가 다르면 확실히 다른 그림이다
ls -l chrome/1200x628.png safari/1200x628.png
# 픽셀 차이까지 보려면 (ImageMagick)
magick compare -metric AE chrome/1200x628.png safari/1200x628.png diff.png
```

다르면 두 갈래다 — **"다운로드는 Chrome 에서"** 라는 운영 규칙을 두거나,
위 1번(캔버스 전환)으로 근본적으로 없애거나. 캔버스는 이미 그려진 그림이라
굽는 경로에서도 그대로 나온다([coloring.md](./coloring.md) 의 "부수 효과" 참고).

## 피그마와의 관계 — 애초에 픽셀 일치가 아니다

"Safari 가 피그마 디자인을 못 살리는 것 아니냐"는 질문이 나오는데, **피그마도 자기
렌더링 엔진**이라 브라우저와 픽셀이 같았던 적이 없다. 코드에는 그 간극을 실측으로
메운 보정치가 이미 쌓여 있다.

| 값 | 왜 있나 |
|---|---|
| `BG_BLUR_PX = 17.5` | 피그마 블러 반지름 35 는 CSS 표준편차와 단위가 달라 절반 (파워스펙트럼 회귀로 측정) |
| `BG_BLUR_REF_W = 1541` | 피그마는 41개 전부 블러 35 인데 그대로 쓰면 작은 사이즈가 뭉개진다 — 상자 크기에 비례시킴. 주석에 "의도적으로 벗어나는 지점" |
| `HEAD_WRAP_TOLERANCE = 1.03` | 피그마 텍스트 엔진이 브라우저보다 약 1% 좁게 잰다 |
| `EXPORT_BLUR_SCALE = 0.8` | 굽는 쪽이 미리보기보다 뿌옇게 나와서 눌러준다 |

즉 목표는 **"피그마와 같게"가 아니라 "피그마에 맞춰 재현"**이고 그건 이미 되어 있다.
Safari 문제는 그 재현이 **브라우저마다 갈리는** 것이지, 피그마 재현이 틀린 게 아니다.

## 하지 말 것 — 시도했다 되돌린 것들

같은 걸 다시 제안하는 일을 막기 위해 남긴다.

| 시도 | 왜 되돌렸나 |
|---|---|
| **그라데이션 맵을 한 번만 굽고 41장이 공유** (`20f920a` → `713ebae`) | 캔버스 41개를 1개로 줄이는 건 맞는 방향이지만, 굽는 동안 `return null` 로 **배경 엘리먼트를 통째로 없앴다.** 글래스는 "뒤에 그려진 것"을 흐리는 효과라 흐릴 대상이 사라지자 **테두리만 뿌옇고 속은 빈 판**이 됐다. 다시 한다면 엘리먼트는 항상 두고 내용만 갈아끼울 것. |
| **확인창에서 유리 블러 끄기**(`flatGlass`) | 동작은 했지만 줌인하면 유리가 밋밋해진다. 시각 타협이 커서 반려됨. 부하를 줄이려면 가상화 쪽이 낫다. |
| **A 의 배경 확대 보정을 빼기** | A 는 블러가 0 이라 보정이 무의미하다고 판단했는데, 사용자가 보던 증상과 무관했다. 실제 원인은 위 증상 1·2 였다. |
| **Anniversary 색을 진하게 / LUT 전환 구간 조정** | 색감 취향 조정이었고 두 번 다 반려됐다. 배경 문제와도 무관했다. |
